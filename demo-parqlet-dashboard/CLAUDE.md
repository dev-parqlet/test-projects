# Parqlet Admin Dashboard — Designer Dev Setup

## Running Locally

```bash
npm run dev -- --port 3005
```

Open **http://localhost:3005** — mock data loads automatically.

**No backend needed** — all API data comes from `app/lib/mock-data/*.json` via local Next.js API routes.

## Staging ("dev") Environment

A parallel staging dashboard runs at **https://dev.parqlet.com**, proxied to
the staging API at `https://api.dev.parqlet.com`. Same code on a separate
GCP VM (`parqlet-api-dev` — provisioned by
`parqlet-backend/infra/bootstrap-dev.sh`).

### Switching the local dashboard against staging

To run the local dev dashboard against the real staging backend (instead of
mock data), point `NEXT_PUBLIC_API_URL` at staging:

```bash
# .env.local
NEXT_PUBLIC_MOCK_ENABLED=false
NEXT_PUBLIC_API_URL=https://dev.parqlet.com
```

This will proxy through your local Next.js dev server's `/api/*` routes to
`api.dev.parqlet.com`. Useful when you want to test a real backend change
without first deploying the dashboard to the dev VM.

### Deploy flow

| Trigger | Target |
|---|---|
| `push` to `main` | production (`dashboard.parqlet.com`) |
| `push` to `dev` | staging (`dev.parqlet.com`) |
| `workflow_dispatch` (env picker) | whichever you choose |

The deploy workflow (`.github/workflows/deploy.yml`) reads the env-scoped
`STAGING_NEXT_PUBLIC_STRIPE_PUBLISHABLE_KEY` / `STAGING_VM_*` secrets when
targeting staging.

### Rollback

`.github/workflows/rollback.yml` accepts `environment` (production | staging)
and `target` (previous | latest | dev-previous | dev-latest | sha).

## Mock Data Mode

Toggle mock/proxy mode by editing `.env.local`:

```
NEXT_PUBLIC_MOCK_ENABLED=true   ← uses local JSON files (no backend needed)
NEXT_PUBLIC_MOCK_ENABLED=false  ← proxies to api.parqlet.com (needs auth)
```

When `MOCK_ENABLED=true`, the Next.js API routes (`app/api/*/route.ts`) read from
`app/lib/mock-data/*.json` instead of proxying to the real backend.

When `MOCK_ENABLED=false`, they proxy to `NEXT_PUBLIC_API_URL` (api.parqlet.com).

All mock data lives in `app/lib/mock-data/` — edit JSON files directly to change data.

> **What was dumped:** The mock data was generated by querying the production
> PostgreSQL database via Docker (`parqlet-backend-db-1`). The API responses
> (camelCase, enriched) were captured from `api.parqlet.com` and saved directly
> as JSON files. The data includes 3 buildings, 150+ residents, 30 bookings,
> 5 alerts, 6 subscriptions, 2 team members, etc.

## Important

- Always run on **port 3005** (this is the only port the app uses)
- `NEXT_PUBLIC_API_URL=http://localhost:3005` — API calls go to the Next.js dev
  server's own API routes, not directly to the backend. These routes either
  serve mock JSON or proxy to `api.parqlet.com`.
- To proxy to the real backend instead of mock data: set
  `NEXT_PUBLIC_MOCK_ENABLED=false` in `.env.local` and restart.
- Shared handler: `app/lib/handle-request.ts` — all API routes use this.
- Mock JSON files: `app/lib/mock-data/*.json`
